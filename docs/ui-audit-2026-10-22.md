# Local UI audit — 2026-10-22

The running installation at `http://localhost:8080` was inspected with Chrome
through Playwright. It held about 17,646 Catalogue Videos. The baseline was
commit `5e49c93`, running image `prdb-fab:0.23.0-local-sabnzbd-ui`.

## Coverage

- Opened 24 main and settings routes on the running production bundle.
- Checked Catalogue search, clearing, browser Back, Site and Actor details,
  Preview stepping/closing, contextual Releases and mobile navigation.
- Checked the corrected frontend through 72 route visits: 24 routes at each of
  320, 390 and 1440 px, including new Indexer and Automation Rule forms.
- Simulated failed reads, successful Wanted writes and slow paging in the
  browser. Wanted simulations did not write to the real account.
- The Library, Downloads and Review Queue were empty. Populated filing flows,
  actual Downloads, deletion, Backup/Restore and saving external connection
  credentials were not exercised. This is not an end-to-end acquisition test.

No JavaScript exceptions or horizontal document overflow were observed in the
tested successful states. Browsing a Preview may request its normal governed
artwork work; the audit did not start Manual Searches or Downloads.

## Fixed

1. **Stale Search and Preview after actions.** Their query keys sat outside the
   Catalogue prefix invalidated by Wanted and Download actions. Both now share
   that prefix. A simulated Wanted write changed the visible button immediately;
   Search reads increased from one to two, and a subsequent Preview write
   refreshed both the list and Preview. The old UI performed no list refresh.
2. **Read failures looked like empty data.** What's new and Wanted displayed
   "Nothing yet" or "Your wanted list has not been read yet" after HTTP 500.
   They now use the existing alert/retry presentation. Both recovered after
   removing the simulated failure and pressing Try again.
3. **Incorrect control labels.** Library nested Verification inside the Sort by
   label, leaving the sort control unnamed and stretching the mobile layout.
   Each now has its own label. Site/Actor directory searches also have accessible
   names independent of their placeholders.
4. **Lost keyboard focus.** Closing Preview left focus on the document body.
   Escape and browser Back now restore it to the last viewed Video's card,
   including after stepping to another Video.
5. **Invalid page input.** Fractional, non-finite, negative and out-of-Int32
   values reached integer API parameters and could fail the read. All ten
   paginated screens now use one parser. `1.5`, `Infinity`, `2147483648`, `-2`
   and `abc` were verified to request page 1 successfully. Valid but out-of-range
   pages remain a separate usability issue below.
6. **Misleading Download guidance.** What's new and Wanted now explain that
   Download starts the best eligible Release at the preferred Quality or below;
   Search opens the Release page.

opportunity: static assets are currently transferred uncompressed. Local data
reads did not show a blocking performance problem in this dataset.

## Validation and local installation

`npm run lint`, `npm run build` and `git diff --check` passed. The audit used
temporary browser checks rather than adding a component-test framework, in
line with ADR 0036/0042/0058. No backend contracts or database schemas changed.

The built frontend was copied into the running local container's
`/application/wwwroot`, publishing the new entry document after its assets.
Previous hashed assets remain available to already-open tabs. The original
entry document is retained locally under
`.scratch/ui-audit/original-index.html` for rollback.

The source changes are on `codex/ui-audit-fixes`. This updates the running
container, not its Docker image: rebuilding an image from this branch is
necessary before recreating the container if the fixes are to survive that
recreation. An ordinary restart retains them.

## Browsing follow-up verification

The remaining browsing changes were checked on a production frontend served by
Kestrel from an isolated local data directory. Browser checks used intercepted
local API fixtures for state changes and failures; no real account preferences,
Downloads, remote searches or reporting settings were changed. No frontend test
framework or runtime dependency was added.

### Asset transfer

The same final bundle was loaded in fresh Chrome browser contexts, three times
with `Accept-Encoding: identity` and three times with Brotli enabled. The CDP
network profile was 1.6 Mbit/s download and 150 ms latency, at 1440 × 1000 px.
The Catalogue response was a fixed local one-Video fixture without artwork, so
these compare the transfer change under controlled conditions; they are not
field measurements or a direct repeat of the populated installation's LCP.

| Measurement | Uncompressed | Brotli |
| --- | ---: | ---: |
| JS encoded body | 504,533 bytes | 145,856 bytes |
| CSS encoded body | 79,666 bytes | 15,527 bytes |
| Combined encoded body | 584,199 bytes | 161,383 bytes |
| Median LCP | 3,340 ms | 1,180 ms |
| Median DOMContentLoaded | 3,275 ms | 1,156 ms |
| CLS, each run | 0 | 0 |
| Long tasks, each run | 0 | 0 |

Brotli reduces the combined body by 72%; median LCP improves by 65%. These
samples do not justify adding route splitting in this change. Both Brotli and
gzip use the platform's optimal compression level and apply only to public
frontend responses. API responses remain outside compression.

A separate browser run without interception verified that cold assets transfer
and subsequent navigation uses cached hashed JS/CSS with zero transferred bytes.
Both `/` and a settings deep link return `Cache-Control: no-cache` for the entry
document. Hashed assets return `public, max-age=31536000, immutable`. Host tests
exercise gzip/Brotli decompression, the entry document with an old ETag after an
upgrade, a changed asset name, un-hashed asset revalidation, API exclusion and an
authenticated Backup's unchanged `no-store` behavior.

### Interaction checks

At 390 and 1440 px, the checks covered:

- Account and Backup deep links on narrow screens without unrelated summary or
  Status reads; the prdb form's independent connection read; resizing in both
  directions; cached return to the Settings index; and a simulated Library
  setting save followed by the updated summary.
- A one-second delayed page read retaining the previous cards with their actual
  page label, visible loading text and `aria-busy`; disabled repeated paging;
  Back/Forward; failure and explicit retry; oversized valid pages; last-page
  shrinkage; recovery on Library, Downloads and Review Queue; and Preview state
  retained on an unavailable Catalogue page.
- One shared hourly-budget explanation with affected work and destinations in
  expandable detail; a distinct reserve cause and a separate Gap; retry times
  in the browser's local timezone; and removal on the next five-second poll.
- Empty Library guidance, a populated Library filtered to zero, a filter reset
  that preserves sorting, Downloads guidance, an idle Review Queue and a
  reason-filter miss. Links were exercised with the keyboard on mobile. No
  acquisition or remote-search writes were issued.

No JavaScript exceptions or horizontal overflow occurred in these checks.
`dotnet build`, frontend build/lint and API regeneration checks pass. The local
full suite recorded 977 passing tests, one skipped cross-filesystem test and
one existing failure in `DirectoryTests.Two_directories_on_one_volume_share_a_filesystem`:
this macOS host cannot read Linux's mount table. The changed Host and Status
tests pass; Linux CI is the final full-suite and container check.
